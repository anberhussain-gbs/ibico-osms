Audit Logs                      │\n        └────────────────────────────────────┘\n```\n\n## Key Components\n\n### Frontend Architecture\n\n**Component Structure:**\n- **Presentational Components**: Reusable UI components (Button, Card, Modal)\n- **Container Components**: Smart components with state management\n- **Page Components**: Full page layouts\n- **Custom Hooks**: Reusable logic (useOrgChart, useEmployee, useSearch)\n\n**State Management (Zustand):**\n- `employeeStore`: Employee data and operations\n- `departmentStore`: Department data\n- `uiStore`: UI state (theme, modals, sidebar)\n- `authStore`: Authentication state\n- `orgChartStore`: Organization chart state\n\n**Services:**\n- `employeeService`: Employee API calls\n- `departmentService`: Department API calls\n- `authService`: Authentication\n- `analyticsService`: Analytics data fetching\n\n### Backend Architecture\n\n**Layered Structure:**\n1. **Controllers**: API endpoints\n2. **Services**: Business logic\n3. **Repositories**: Data access (with Unit of Work pattern)\n4. **Models**: Domain models\n5. **DTOs**: Data transfer objects\n6. **Middleware**: Cross-cutting concerns\n\n**Key Services:**\n- `EmployeeService`: Employee management\n- `DepartmentService`: Department management\n- `OrgChartService`: Organogram generation\n- `AuthorizationService`: Role-based access\n- `AuditService`: Change tracking\n- `ImportExportService`: Excel operations\n\n### Database Architecture\n\n**Core Tables:**\n- `Employees`: Employee master data\n- `Departments`: Department information\n- `Designations`: Job designations\n- `EmployeeDesignationHistories`: Career progression\n- `ManagerReportingRelationships`: Hierarchy\n- `TransferHistories`: Audit trail\n- `Roles`: User roles\n- `UserAccounts`: User authentication\n- `AuditLogs`: System audit trail\n- `Vacancies`: Vacant positions\n\n## Authentication & Authorization\n\n**JWT Flow:**\n1. User login with credentials\n2. Validate against `UserAccounts` table\n3. Generate JWT token with claims\n4. Token includes: UserId, Email, Roles, Department\n5. Token stored in localStorage\n6. Sent in Authorization header for API calls\n\n**Role-Based Access Control:**\n- **Super Admin**: Full system access\n- **HR Admin**: Employee management\n- **Department Manager**: Department-level access\n- **Employee**: View-only access\n\n## Data Flow\n\n### Employee Creation Flow\n```\nUser Input → Form Validation → API Call\n  ↓\nBackend Receives → Validate Data → Check Authorization\n  ↓\nBusiness Logic → Calculate Hierarchy → Save to Database\n  ↓\nAudit Log Entry → Return Response\n  ↓\nFrontend Updates Store → UI Refresh → Organogram Regenerates\n```\n\n### Organogram Generation Flow\n```\nFetch All Employees → Build Hierarchy Tree\n  ↓\nFind CEO/Top Node (ReportTo = NULL)\n  ↓\nRecursively Build Children for Each Node\n  ↓\nApply Filters/Search if needed\n  ↓\nFormat Data for React Flow\n  ↓\nRender on Canvas\n```\n\n## Performance Considerations\n\n1. **Database Optimization**\n   - Indexes on ManagerId, DepartmentId, EmployeeId\n   - Efficient hierarchy queries\n   - Caching frequently accessed data\n\n2. **Frontend Optimization**\n   - Virtual scrolling for large lists\n   - Memoization of components\n   - Code splitting\n   - Lazy loading images\n\n3. **API Optimization**\n   - Pagination for list endpoints\n   - Response compression\n   - Caching headers\n   - Batch operations for bulk imports\n\n## Security\n\n1. **Authentication**: JWT tokens with expiration\n2. **Authorization**: Role-based access control\n3. **Input Validation**: Server-side validation\n4. **SQL Injection Prevention**: Parameterized queries via EF Core\n5. **CORS**: Configured for frontend domain\n6. **Password**: Hashed using bcrypt/PBKDF2\n7. **Audit Logging**: All changes tracked\n
